# Sovereign Licensing Bridge & Gating Engine Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and wire an automated online/offline licensing bridge connecting the Agentic Professionals cloud portal (`https://app-apnet-net.onrender.com`) to the Hayagriva Desktop IDE, enabling seamless 1-click activation, hardware locking, and air-gapped sovereign enforcement for hundreds of legal practitioners.

**Architecture:** The desktop IDE's local Node.js backend intercepts raw portal keys (`HAYA-STR-...`), performs a 500ms HTTPS handshake with the cloud portal's `/api/v1/activate` endpoint using the local machine hardware fingerprint (`MAC-...`), receives a cryptographically signed HMAC-SHA256 offline token, and locks it into the local SQLite licensing vault (`~/.hayagriva/license_vault.db`). Unactivated chambers retain 100% lifetime free access to document ingestion, search, and Monaco editing, while Autonomous AI agents (`@Advisor`, `@Forms`, `@Document`) and bare act statutory vaults are cleanly gated.

**Tech Stack:** Node.js, Next.js 15, Neon Serverless PostgreSQL, SQLite (`node:sqlite DatabaseSync`), HMAC-SHA256 crypto, Theia IDE Extension Framework (TypeScript).

**Spec:** [`docs/superpowers/specs/2026-10-03-licensing-bridge-and-gating-design.md`](file:///Users/atulgrover/Desktop/HAYAGRIVA/harness/docs/superpowers/specs/2026-10-03-licensing-bridge-and-gating-design.md)

## Global Constraints
- Signing secret default: `hayagriva_sovereign_chamber_secret_key_2026` (overridable via `HAYAGRIVA_LICENSE_SECRET`).
- Cloud Activation URL: `https://app-apnet-net.onrender.com/api/v1/activate`.
- Core Workbench Immunity: Document ingestion, PDF parsing, FTS5 local search, PageIndex browsing, and Monaco text editing must never be blocked when unactivated.
- Zero-leak sovereignty: No client document text, case files, or case names are ever sent to the cloud licensing portal during activation. Only `{ license_key, hardware_fingerprint, device_name, os_info, app_version }` are transmitted.

## Review Focus
1. **Raw key format pasted into offline validator:** The validator must distinguish raw keys (`HAYA-STR-...`) from signed token envelopes (`<payload>.<sig>`) and delegate raw keys to the cloud handshake instead of throwing a parsing exception.
2. **Offline Chamber Boot without Internet:** An already activated IDE must boot with 0 network calls and 0ms latency from `license_vault.db`.
3. **Device Limit Exceeded (403):** When a user activates on a 2nd machine under a 1-device Starter license, the error must cleanly direct them to `https://app-apnet-net.onrender.com/dashboard/licenses` to deactivate old machines.
4. **Clock Tampering vs NTP Sync:** Clock drift within $\pm 5$ minutes must be tolerated without tripping anti-tamper latch.
5. **Entitlements File Resilience:** If `active_license_entitlements.json` is missing or corrupted, the system must self-heal from SQLite `license_state` table.
